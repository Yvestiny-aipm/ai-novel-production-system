## 备份实现

新增 `backend/backup_restore.py` 与 `integration/manage_backup.py`，采用 SQLite online backup API，拒绝覆盖已有备份或恢复目标。每个备份目录保存：

- `database.sqlite`：业务数据及 `harness_calls`；
- Contract Schema、枚举、模型路由配置和迁移文件；
- `manifest.json`：备份状态、迁移版本、文件大小与 SHA-256；
- 不保存 API Key，模型配置只保存环境变量引用。

恢复前会校验所有文件哈希、SQLite `integrity_check` 与 `foreign_key_check`；恢复目标必须是不存在的新路径。恢复状态记录在恢复库旁的 `*.restore.json`，使用 `restore_testing`、`restore_success` 或 `restore_failed`。

历史恢复采用仅插入语义：同编号内容完全相同才视为已恢复；同编号内容不同返回 `RESTORE_HISTORY_CONFLICT`，绝不覆盖既有正文、报告、提案或记忆。

## TaskState 与恢复规则

- `status` 决定是否可运行：`completed` 跳过、`waiting_confirmation`/`blocked`/`paused` 停止、`queued` 在前置全部完成后才可运行。
- `current_node` 是当前或最后业务节点；当 `status=completed` 时，`human_confirmation` 或 `memory_processing` 仅表示最后处理位置，前端不得显示为处理中。
- 恢复只复用通过校验的持久化 checkpoint；新版本只由明确的返工动作创建。
- 恢复单条或单场时，任何同编号但不同内容的行都会失败，不执行替换。
