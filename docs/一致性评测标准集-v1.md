# 小说一致性评测标准集 v1

> 用途：审查单场、跨场、跨章及全书正文的一致性；也可用于检查规划、正文、审查和记忆之间的信息传递。本文件定义应如何评测，不表示项目代码已经实现全部规则。

## 1. 评测对象与边界

### 1.1 两种模式必须分开

| 模式 | 评测依据 | 可以得出的结论 |
| --- | --- | --- |
| 正文一致性（默认） | 同一作品当前生效版本的正文；若章名、附录、人物表属于读者实际看到的作品，也一并纳入 | 正文内部是否自洽 |
| 生产链一致性（明确指定时） | 正文及其对应版本的规划、资料包、审查报告、已确认记忆、作品设定 | 问题最早在哪个环节产生，在哪个环节本应发现或阻止 |

正文模式不得拿测试样例、未采纳的大纲、旧草稿、待确认记忆提案或模型自述，判定当前正文有错。生产链模式也要区分“正文事实矛盾”和“正文未遵守生产要求”，不能混报。

### 1.2 只比较正确版本

1. 每场只取当前生效的正文版本，并记录作品、章、场和正文版本；返工前的旧稿只用于追溯错误来源。
2. 场次按作品实际阅读顺序排列。插叙、倒叙、回忆、梦境和文中档案另建时间轴，不按出现顺序误判事件顺序。
3. 未完稿只评估已经写出的部分；尚未揭晓的悬念不是一致性错误。
4. 资料缺失时标记“无法判断”，不把“没查到矛盾”写成“已证实一致”。

## 2. 什么才算一致性问题

**一致性问题**：同一对象、同一事件或同一状态在可比较条件下出现不能同时成立的陈述；或者后一场使用了此前尚未获得的信息、物件、权限或能力，且正文没有给出取得过程。

判断前必须核对四件事：

1. **是否同一对象**：同名不同人、同名不同档案、同一地点的前后门，都可能消除表面矛盾。
2. **是否同一时点**：旧案发生时与当前调查时、昨日与今日、计划与执行不可混为一谈。
3. **是否同一断言层级**：叙述者直述、人物回忆、档案记载、猜测和传闻必须分别记录。
4. **是否有正文解释**：失忆、撒谎、记录错误、补录、转场省略等若已明确写出，可使冲突成为剧情线索；仅靠评测者替作者补设定，不算解释。

人物证词与档案不一致，首先标记为**故事内证据冲突**。只有正文把两者误称为吻合，或后续未经核实就按其中一方建立确定事实时，才升级为叙事一致性错误。

## 3. 必查项目

| 编号 | 维度 | 核对问题 | 典型失败 |
| --- | --- | --- | --- |
| C01 | 时间线 | 事件发生日、距今时长、先后顺序、一天内时段、路程与耗时是否兼容？是否区分旧案时间与调查时间？ | 连续行动中“失踪十九天”变成“失踪多年”，且没有跳时说明 |
| C02 | 人物身份与关系 | 姓名、年龄、亲属关系、职务、阵营、在场和离场状态是否一致？同名者是否被唯一核认？ | 未查工号就把两个同名者视为一人 |
| C03 | 人物知识边界 | 人物此时知道什么、亲眼见过什么、只听谁说过什么？是否提前使用未知信息？ | 只取得索引的纸条，下一场已写有交接人姓名 |
| C04 | 物件与文书状态 | 物件名称、编号、页码、栏位、内容、归属、损坏程度、持有人和取得途径是否连续？ | 同一人事卡的岗位原文被无说明地改写 |
| C05 | 地点与行动 | 人物从哪里出发、到哪里结束，门是否开着、物件是否带走；相邻场景的行动能否接上？ | 上场锁门离开找人，下场直接进入屋内，关键经过未交代 |
| C06 | 事件与因果 | 已发生的动作、发现、承诺、决定和后果是否被保留？推断是否被写成事实？ | 仅证明船靠岸，后文写成某人已从船上下来 |
| C07 | 世界规则与能力 | 正文已建立的技术、制度、代价、限制和例外是否稳定？新例外是否先建立？ | 能力代价被无说明地免除 |
| C08 | 未决问题状态 | 悬念是未证、部分证实还是已解决？后文是否重复“首次发现”或让已解决问题无故回到未知？ | 已取得原件，下一场又写成只见过目录 |
| C09 | 叙述与证据关系 | 引述、摘录、见证、转述与角色笔记是否忠实对应？相互冲突的来源有无标明分歧？ | 证人称下午离岗、登记称午前离岗，叙述却说二者互证 |
| C10 | 全书长期锚点 | 核心事件日期、关键身份、不可逆事件、稳定物证、世界规则是否跨章保留？ | 早期确立的失踪时长在后续章节漂移 |

重复、节奏慢、悬念久未揭晓、章名吸引力不足，原则上属于剧情或阅读体验评价。只有它们造成事实状态前后不一致时，才进入本标准。

## 4. 证据强度与结论标签

每条候选问题都要同时保存**原文证据**和**判断强度**。

| 标签 | 使用条件 | 处理 |
| --- | --- | --- |
| 确认矛盾 | 两处原文指向同一对象、同一时间或同一状态；不能同时成立；正文无解释 | 列为必须修复 |
| 确认断链 | 后文使用的信息、物件或权限，在此前的明示范围内尚不存在或尚未取得；关键取得步骤缺失 | 影响因果或调查结论时必须修复 |
| 故事内冲突 | 证词、档案、人物看法互相矛盾，但正文承认来源不同且未冒充定论 | 保留为线索，检查后续是否处理 |
| 高风险疑点 | 表面冲突成立，但同名、跳时、转场、叙述视角等可能解释仍未排除 | 待核；不得写成已确认错误 |
| 表达衔接缺口 | 读者难以接上动作或资料来源，但不影响已知事实与核心因果 | 建议补一句或补一段，不自动判定全场失败 |
| 无法判断 | 缺少正确版本、前场原文或决定性上下文 | 补取材料；不宣称通过 |

**禁止的推理**：用数据库字段“已确认”代替用户采纳；用审查报告的“通过”代替正文核验；把人物说的话自动当作叙述事实；把尚未出现的解释当作已经写出的解释。

## 5. 严重程度与通过规则

| 等级 | 条件 | 当前系统报告映射建议 |
| --- | --- | --- |
| S1 严重 | 改变主线因果、核心时间线、关键身份、世界规则，或使后续多场建立在错误状态上 | `serious`、跨场或全书影响，必须返工或裁决 |
| S2 普通硬问题 | 可定位的跨场物证、人物知识、地点或行动矛盾，影响本场事实理解或调查可信度 | `ordinary`，必须修复后通过 |
| S3 轻微衔接 | 可用简短交代修补，且不改变已经成立的事实 | 通常为建议；若导致关键证据凭空出现则升为 S2 |
| W 待核 | 证据不足或属于故事内冲突，尚不能判定作者写错 | 不计必须修复项；持续跟踪 |

**通过条件**：正确版本和必要前文齐备；C01—C10 已按相关性检查；无未解决的 S1/S2；W 项注明缺口与下一步核验方法。当前 `ReviewerResult` 只有 `passed` / `failed`，S1/S2 应进入 `findings`；S3 可进入 `suggestions`；W 不应伪装成已证实的 `finding`。

## 6. 单条问题的记录格式

每项报告至少写：

```text
问题编号、维度、结论标签、严重程度、影响范围
涉及版本：作品 / 章 / 场 / 正文版本
证据 A：原文短引 + 精确位置 + 说话者/叙述层级
证据 B：原文短引 + 精确位置 + 说话者/叙述层级
冲突点：为什么两个陈述不能同时成立，或哪一步信息来源缺失
可能解释：正文已有解释 / 尚未写出的可能解释（分别列明）
最小修复：改哪一处、补哪条取得或核对过程
生产链归因（可选）：最早产生环节 / 信息传递缺口 / 漏检环节
```

原文引述必须能在对应正文版本逐字找到。只给“第几章有问题”或“感觉不连贯”，不构成可执行的评测结果。

## 7. 评测流程

1. **锁定版本**：列出当前正文的章、场、版本和顺序；排除旧稿。没有当前版本清单则先停止判定。
2. **建事实账**：按角色、时间、地点、物件、规则、未决问题登记关键断言，保留来源和确定性，尤其记录不可逆事件与核心时间锚点。
3. **逐场检查**：核对本场内部及相邻两场的进入状态、退出状态、知识与物件交接。
4. **跨章回查**：对每个新断言检索同一对象此前的首次出现和最近一次变化；至少回查关键时间、身份、物证原文，不只看概括摘要。
5. **排除伪冲突**：检查同名、不同时间、不同叙述层级、明确的补录或撒谎设定。证据冲突与作者错误分开。
6. **定级与修复**：按第4、5节定结论和严重程度，给出最小改动位置；无法判断的列出缺什么原文。
7. **生产链复盘（可选）**：依次查看当场资料包、规划、正文、审查意见及已确认记忆，分别标出“产生”“未提供”“未拦截”，不把最后发现问题的板块自动认作根因。

## 8. 用《潮痕档案》校准边界

以下只用于说明判法，不预设修稿方向：

| 现象 | 应判为 | 理由 |
| --- | --- | --- |
| 第1—5场称失踪十九天，第10场称现场已过几年；中间连续行动且无跳时 | 确认矛盾，S1 | 同一失踪事件距今时长不能同时成立 |
| 第7场只取得交接索引，第8场出发时纸条已有“吴”和班次 | 确认断链，S2 | 缺少取得姓名与班次的正文过程 |
| 谭桂山说下午离岗，门岗登记写午前 | 故事内冲突，W；若正文称两者互证，则该判断为 S2 | 证人可记错、登记也可错；作者须保留分歧 |
| 周进海卡片岗位两种说法 | 高风险疑点；核实同一张卡与是否有第二栏后再定 | 不能仅凭措辞差异断言卡面事实改变 |
| 第9场去找老账房，第10场遇葛看管并进入过磅房 | 表达衔接缺口，S3；若后续依赖未经取得的钥匙或许可，再升 S2 | 现有正文缺少转接，但不必然构成事实矛盾 |

## 9. 与当前项目实现的关系

本标准是**目标评测规程**，不是现有自动关卡清单。当前代码能检查部分角色/设定规则、有限的世界状态措辞、已发生事实的特定否定句、重复和规划推进；它没有实现对全部 C01—C10 的逐项语义核验，也不能仅凭 `QualityReport.status=passed` 证明全书一致。评测输入若没有关键原文或已确认记忆，应先标“无法判断”，补足来源后再判。
